# Herdr Desktop embedding

The first Herdr milestone is to prove that an interactive Herdr Desktop layout can run inside
Sylph. The terminal chooser, expand and restore controls, and layout importer follow this proof.
This document records the design investigation. An embedded Desktop view is not implemented yet.

## What Sylph needs to host

Sylph's terminal uses a PTY and a JavaFX WebView running xterm.js. Herdr TUI can use that path,
but Traveler and T3 run against the Herdr Desktop layout and mod APIs. Desktop mods describe
native GPUI elements in JavaScript. Herdr Desktop renders those elements and talks to herdr-core,
which owns the terminals and agent sessions.
[Herdr mod API guide](https://github.com/herdrdev/herdr-app/blob/master/defaults/AGENTS.md)

Traveler needs its theme, art and custom blocks. T3 needs its layout, mods and context-specific
keybindings. Both need a real Desktop mod runtime for full compatibility.
[Traveler recipe](https://raw.githubusercontent.com/franky5440-afk/herdr-traveler/main/RECIPE.md) ·
[T3 recipe](https://raw.githubusercontent.com/JinJieBeWater/herdr-t3/main/RECIPE.md)

## First prototype

Start on Linux Wayland with Herdr App 0.1.18 source at
`3e6d56448272064fd06ed95f5b7dc2cf70ea67b4`. Its startup connects to herdr-core, initializes mods
inside the GPUI application loop, and creates the layout in a native `AppWindow`. This gives the
prototype a concrete window creation point to investigate.
[Pinned entry point](https://github.com/herdrdev/herdr-app/blob/3e6d56448272064fd06ed95f5b7dc2cf70ea67b4/src/main.rs#L185-L259)

Use GPUI's existing `render_current_to_image` as the first pixel transfer experiment. Herdr
already uses it for screenshots. Test whether a helper can deliver frames into a JavaFX view
at interactive speed and receive focus, pointer, keyboard and resize events for that view.
The screenshot code establishes that GPUI can produce pixels from an existing window. It
does not establish efficient streaming, windowless rendering, or input forwarding.
[Pinned screenshot implementation](https://github.com/herdrdev/herdr-app/blob/3e6d56448272064fd06ed95f5b7dc2cf70ea67b4/src/control.rs#L148-L165)

Start with a small GPUI view, then a stock Herdr layout and one local shell. Keep terminal
lifecycle with herdr-core. Use a temporary Herdr App profile and an isolated test session.
The investigation machine reports a Wayland session. Rust, Cargo, Zig, Just, Herdr App and
`hc` were unavailable on its PATH, so the GPUI path has only been checked against upstream source.

## JavaFX transport experiment

The [frame demo](../experiments/herdr-embedding/FrameBridgeDemo.java) displays raw BGRA frames
generated by a separate [Python fixture](../experiments/herdr-embedding/render_fixture.py).
JavaFX sends the surface size, pointer position, focus state and last typed character through
pipes. One exchange runs on a worker at a time and the JavaFX thread presents the result.
The demo caps frames at 960 × 540 and stops its helper when closed.

From the repository root with JDK 21 and Python 3 available:

```sh
./init.sh --java-only
./gradlew :app:herdrFrameExperiment --no-configuration-cache
```

Click the preview and type to change its background. Move the pointer to move the marker,
resize the window to change the displayed frame dimensions, or click the text field to return
focus to a normal input. The experiment starts a separate demo window.

To verify a typed key travels through the helper and changes a pixel in JavaFX without opening
a visible window:

```sh
./gradlew :app:herdrFrameExperiment -PheadlessHerdrExperiment --no-configuration-cache
```

The request format describes simple state and does not preserve a complete input event stream.

## GPUI renderer experiment

The [Rust helper](../experiments/herdr-embedding/gpui/src/main.rs) uses GPUI 0.3.8's headless
renderer to draw a simple scene and read back its pixels. It dispatches pointer movement
and changed typed characters through GPUI handlers. A primary click in JavaFX also sends
its coordinates to the helper, which dispatches mouse down and mouse up through GPUI's
hit testing. Click **Click probe** in the demo to see its background change. This uses the published GPUI crates at
the versions declared by the pinned Herdr App source. It does not load Herdr App's patched
renderer, Desktop layouts, or terminal sessions.

On Linux, build with Rust 1.95 and Cargo. The build needs a C toolchain, pkg-config,
and development libraries for Fontconfig, xkbcommon, Wayland and XCB. Run with Vulkan
available. Mesa's software Vulkan driver works for a headless check.

```sh
cargo build --locked --manifest-path experiments/herdr-embedding/gpui/Cargo.toml
./gradlew :app:herdrFrameExperiment --no-configuration-cache \
  -PheadlessHerdrExperiment \
  -PherdrFrameHelper=experiments/herdr-embedding/gpui/target/debug/sylph-gpui-frame-probe
```

The smoke test fires a JavaFX key event and asserts that GPUI's response changes a pixel
displayed in the JavaFX view. Omit `-PheadlessHerdrExperiment` to try the input and resize
behavior manually.

To test clicks, use the same command with `-PheadlessGpuiClickExperiment` in place of
`-PheadlessHerdrExperiment`. This sends one click outside the button and two at the same
point inside it. The test checks that only the two inside clicks change the button pixels.
The probe transports completed primary clicks. It does not forward drags or send mouse
events to the running Herdr Desktop app.

## Stock Desktop frame preview

The JavaFX demo can also capture the window of a running Herdr Desktop process using its
`shot` command. The preview requests at most two frames per second, preserves their
aspect ratio, and shows a read-only view by default. The Desktop window and core own the
live shell. Resizing the preview scales the image.

On Linux, start Herdr Desktop with a temporary profile and core state for this experiment,
open a shell, and keep the Desktop window open. Launch Gradle from the environment that
points to that same profile (`HERDR_APP_HOME`).

```sh
./gradlew :app:herdrFrameExperiment --no-configuration-cache \
  -PherdrDesktopExecutable=/absolute/path/to/herdr-app
```

Run a command in Herdr Desktop's shell and watch for its output in the preview. Add
`-PheadlessHerdrExperiment` to check that the capture loads in JavaFX without opening a
second window. The Desktop app itself still needs a graphical session.

Verified on Linux Wayland with Herdr App 0.1.18 and herdr-core 0.1.22. A command printed
a marker in a live shell, the stock layout's captured pixels changed, and the JavaFX
headless check loaded the resulting frame.
[Herdr App release manifest](https://releases.herdr.dev/app/0.1.18/manifest.json) ·
[Herdr core release manifest](https://releases.herdr.dev/core/0.1.22/manifest.json)

### Keyboard probe

Use a disposable test shell. Find its local terminal ID with `herdr-app ls` and run the
preview against the same isolated core and Desktop profile:

```sh
./gradlew :app:herdrFrameExperiment --no-configuration-cache \
  -PherdrDesktopExecutable=/absolute/path/to/herdr-app \
  -PherdrCoreExecutable=/absolute/path/to/hc -PherdrTerminal=t1
```

Click the JavaFX preview to type. Input always goes to the displayed **Keyboard target**
ID, even if the original Herdr window switches to another tab. Keep the target shell
visible in Herdr while testing. The probe forwards letters, digits, space, punctuation
accepted by `hc keys`, Enter, Backspace, Tab, Escape, arrow keys, and Ctrl+C.
An unsupported character blocks Enter until Ctrl+C clears the draft in a shell.
The mouse wheel scrolls the target terminal's history and refreshes the captured Desktop
frame. It works while that terminal is visible in Herdr. Clipboard, Unicode input, and
native resizing still need a bridge.

With `-PheadlessHerdrExperiment`, JavaFX sends a draft of `xxY` without submitting it.
Check it with `hc read t1` and clear it with Ctrl+C. Verified with the isolated Wayland
Herdr App and core versions above, including repeated characters and uppercase input.

For a headless wheel check, fill the visible test shell's scrollback, for example with
`seq 1 200 | sed 's/^/Sylph scroll history row /'`. Leave it at the bottom. Use
`-PheadlessHerdrScrollExperiment` with the same Desktop, core and terminal arguments.
The check scrolls toward older output and compares the captured frames.

### Native Desktop input probe

The [input patch](../experiments/herdr-embedding/desktop/sylph-click.patch) adds primary-click,
drag, and keyboard requests to the pinned Herdr App build. JavaFX maps pointer coordinates relative to the
displayed image, excluding the empty space around it. Clicks and keys are sent in order.
GPUI dispatches keys to the newly focused control after a click. This mode supports typed
Unicode characters, basic navigation and editing keys, and Ctrl+C. Wheel scrolling
targets the focused terminal. The stock Herdr binary does not expose these input requests.

Apply the patch to a separate checkout at the pinned revision and build it with the
[upstream build prerequisites](https://github.com/herdrdev/herdr-app/tree/3e6d56448272064fd06ed95f5b7dc2cf70ea67b4#build-from-source).
Start the patched build with `SYLPH_HERDR_CLICK_PROBE=1` and an explicit, private
`HERDR_APP_HOME` directory (mode 0700). Keep the sandbox profile and core state separate
from your normal Herdr session. Run this from Sylph with the same profile:

```sh
./gradlew :app:herdrFrameExperiment --no-configuration-cache \
  -PherdrDesktopExecutable=/absolute/path/to/patched/herdr-app \
  -PherdrDesktopClickProbe
```

Click a visible tab in the frame. Confirm the active tab in the next frame or with
`herdr-app status`. For a headless click, add `-PheadlessHerdrDesktopClick=x,y` with
normalized coordinates from a capture of that same window. This checks delivery and
frame refresh. Use Herdr's status output to verify the action at those coordinates.
To check focus routing as well, add `-PheadlessHerdrNativeInputExperiment`. In a disposable
Herdr space with two fresh shells, point the coordinates at the inactive tab. The test clicks
that tab and types `xxY_é` without submitting it. Confirm with `hc read` that only the newly
selected shell has the draft. The separate stock keyboard probe still uses a fixed target.
IME composition remains open.

### Native viewport resize

Add `-PherdrDesktopResizeProbe` to the native input command. Changing the preview size
asks the patched Herdr window to resize its viewport so its layout and terminal grid
reflow. Changes are sent after a short pause and clamped to 320–1920 by 200–1080 logical
pixels. Keep the separate Herdr window in normal windowed mode during the experiment.
The preview waits for the frame before accepting pointer clicks at the new size.

Add `-PheadlessHerdrDesktopResize` instead to verify two different frame sizes. On
Wayland, `stty size` in the same shell changed from 37 rows by 120 columns to 24 by 86.
The shell PID stayed the same. This still resizes the separate Desktop window. Hosting
the view in an actual Sylph tab remains a follow-up.

### Drag selection

Drag across terminal text in the preview. Herdr applies the drag when you release the
primary button and the preview refreshes the selection. The probe sends the two endpoints,
so it does not show a live highlight or scroll at the edge while dragging.

For a headless delivery check, add `-PheadlessHerdrDesktopDrag=x1,y1,x2,y2` to the native
preview command, using normalized coordinates from the captured frame. Use the patched
`herdr-app sylph-copy` command to verify the selected text. On Wayland, the probe selected
an exact substring from a real shell's output.

### Text clipboard

In native input mode, use **Ctrl+Shift+C** to copy Herdr's terminal selection and
**Ctrl+Shift+V** to paste JavaFX clipboard text into the terminal with keyboard focus.
The bridge also accepts **Cmd+C** and **Cmd+V**. Copy without a selection leaves the
clipboard alone. You can select the text by dragging in either window.

The probe transfers up to 64 KiB of UTF-8 text. Paste accepts a single line without control
characters and uses Herdr's terminal paste encoding. It leaves the pasted text at the shell
prompt for review. Files, images, and multiline paste are outside this checkpoint.

For a headless check, print `SYLPH_COPY_CHECK` in a disposable Herdr shell and select its
text (for example, with `herdr-app do terminal.select_all`). Keep that terminal focused,
then run the native preview command above with `-PheadlessHerdrClipboardExperiment`.
The check reads the selection into the JavaFX clipboard and pastes `Sylph paste é`.
Use `hc read` to confirm it is still a draft at the prompt. Verified on Wayland with the
patched Herdr App.

Verified on Wayland with a patched Herdr App 0.1.18 build. The headless JavaFX click
changed the active tab from `Start here` to `Click me`, confirmed by the Desktop
status response. The combined probe put the draft only in the clicked shell. The
patched app rejected invalid coordinates and clicks with an unsafe profile directory
or without opt-in.

## Native embedding checks

The public Herdr App guide documents a standalone native client. A supported JavaFX embedding
API has not been identified. The upstream experimental GPUI embedding design is useful reference
material, but its demonstrated host is GPUI. JavaFX support and Wayland interaction need a
prototype on a real desktop.
[Herdr App source and build requirements](https://github.com/herdrdev/herdr-app) ·
[Experimental GPUI embedding design](https://github.com/zed-industries/embedded_gpui/blob/main/DESIGN.md)

The prototype passes when:

- A stock Herdr Desktop layout is interactive in a Sylph view on Wayland.
- Keyboard, mouse, clipboard, and resize work. Clicking the editor returns focus to the editor.
- Expanding and restoring the embedded surface preserves a running terminal command.
- Closing and reopening the view follows an explicit session policy and cleans up the helper.
- Pinned, reviewed Traveler and T3 bundles load in the isolated profile with their required assets,
  mod UI, and keybindings. Verify their main interactions visually.

Herdr mods can run programs and read files with the user's permissions. Treat the profile as data
isolation and review the exact bundled mods before loading them.
[Herdr Desktop mod security](https://github.com/herdrdev/herdr-app/blob/master/docs/security.md)

If the prototype cannot provide a stable GPUI surface and input bridge, record the missing upstream
capability before choosing a renderer port or reducing the feature scope.
